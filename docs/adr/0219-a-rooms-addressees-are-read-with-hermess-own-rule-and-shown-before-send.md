# A room's addressees are read with Hermes's own rule and shown before the owner sends

> **Accepted.** The reader is `src/hermes/roomMentions.ts`. The screens are `src/ui/GroupRoomPane.tsx` and `src/ui/GroupRooms.tsx`. The stand-in server keeps its own port in `src/hermes/fakeGroups.ts`. The vectors are cut by `scripts/room-mention-vectors.py` into `src/hermes/roomMentionVectors.json`. Tested in `src/hermes/roomMentions.test.ts`, `src/hermes/roomMentions.property.test.ts`, `src/hermes/roomMentions.vectors.test.ts`, `src/hermes/fakeGroups.test.ts`, `src/ui/groupRooms.test.tsx`, `src/ui/groupRoomsTranslated.test.tsx` and `e2e/features/group-rooms.e2e.tsx`. It builds on ADR 0210 and changes none of its decisions.

The owner wanted `@bram` in a Group room to send the turn to Bram and nobody else, and to see before pressing Enter who Hermes would hand the message to.

A room message has no addressee. `groups.send` takes `{text, thread_id, attachments?}`, and Hermes decides who answers by scanning the text with `_MENTION_RE` and `resolve_mentions` in `gateway/hosted_room_discussion.py`. The client can't address anyone. It can only predict what Hermes will do, and a prediction helps only if it is exactly Hermes's rule.

Four facts shaped the design. Each was read from Hermes at `f0d94882`, whose routing is the same as `ae2a81cc`'s, or measured by running its two functions on 2026-11-18.

- **The regex has no left boundary and ignores code.** `me@example.com`, `` `@ada` `` and a fenced `@ada` all reach Ada. A word the regex captures whole, such as `bram.`, finds no bot, so `Thanks @bram. Can you look?` names nobody and goes to everyone.
- **Python's ignore-case reads four more letters than the pattern shows.** On a `str` pattern `re.IGNORECASE` widens `[A-Za-z]` to U+0130 (`İ`), U+0131 (`ı`), U+017F (`ſ`) and U+212A (the Kelvin sign). `str.casefold()` then reads them as `i` with a combining dot, `ı`, `s` and `k`. Hermes sends `@Kim` (Kelvin sign) to Kim and reads `@adaſ` as the handle `adas`. The client's and the stand-in's old regex, `[A-Za-z0-9]` with `toLowerCase`, read the first as nobody and the second as Ada.
- **An owner's message goes to everyone when it names nobody.** `resolve_mentions` takes `default_all=True` for it and returns the named members in roster order, not in the order typed. A bot's reply uses `default_all=False`.
- **A bot's reply that names a seat brings it into the next round.** That is `_unaddressed_member_mentions`. It is not part of what the owner sends.

## Decisions

- **One reader.** `roomMentions.ts` holds the only client copy of Hermes's mention grammar and fold. `goesTo`, the picker, `asksOwner` and `carryOnDraft` all read through it, and `groupRooms.ts` no longer has a regex of its own. The regex spells the four letters as escapes, and `fold` is `toLowerCase` plus the long s to `s`, which is `str.casefold()` on every string the regex can capture.
- **The text is never rewritten.** A warning explains a surprise and the message goes out as typed. The send path is unchanged: `onSay(draft.trim())`, then `store.say`, then `groups.send`.
- **`goesTo` answers both questions in one pass.** It returns `{to, mentions}`. `to` is a union, `everyone` (because nobody or `@all` was named) or a non-empty tuple of seats in roster order, so an empty list of recipients can't be drawn. `to` is folded from the mentions that carry a target, so the line and its notes can't disagree. It takes any string and any roster, and the seats it returns are the caller's own objects.
- **A mention is a union on two questions.** Did the owner mean a mention (the `@` starts a word and is outside code), and does Hermes route on it. Meant and routed is `plain`. Not meant and routed is `inCode` or `glued`, and carries its target because the message goes there anyway. Meant and not routed is `trailing` (`@bram.`, with the mark Hermes took for part of the name) or `unknown`, and carries no target because it reaches nobody. Not meant and not routed (`me@example.com`, `` `@Injectable` ``) is not reported, since it surprises nobody. The pane reads whether a note's kind still routes from one table, `STILL_ROUTED` in `GroupRoomPane.tsx`, which has a row for each kind, so a new kind does not compile until it says.
- **Code is what CommonMark says it is.** `codeRanges` takes the `inlineCode` and `code` nodes from `mdast-util-from-markdown`, because the bots' models read the message as Markdown. An unclosed backtick is not code. An unclosed fence runs to the end. The message is sent trimmed, so leading spaces are not read as an indented block.
- **The parser is skipped where it is quadratic.** On one line that nests list items, its time roughly quadruples as the count doubles: 135 ms for 1,000, 574 ms for 2,000 and 2.5 s for 4,000 (measured with `mdast-util-from-markdown` under Node 22). `goesTo` runs on every keystroke. A text past 16 KB, or with a line that opens 24 block quotes or list items, is not read for code. Routing never depends on code, so this only drops the "in code" note.
- **The Goes-to line shows for any non-blank draft.** "Everyone (no bot named)" is the costliest outcome, up to six bots answering, so it is the one the owner most needs to see. The line says who gets the first round. A pull-in from a bot's reply isn't previewed, since it depends on what the bots write. Only the sentence saying who it goes to is a live region (`role="status"`, `aria-atomic`), always mounted, and its text changes only when the answer does, so a screen reader hears it once, not for each keystroke. The notes sit beside it, outside the live region, because a note about a name still being typed ("No one in this room is @q", "@qu", ...) changes with every key. The textarea's `aria-describedby` points at both while the draft has text. At most three notes show, then "and N more".
- **A note for the word the picker is offering rows for is held back.** While `@b` has rows, Enter completes it and can't send, so nothing goes out unwarned, and "No one in this room is @b" would be noise.
- **The picker shows who each bot is.** A row has the bot's colour, name, `@handle` and one-line description, then Everyone with `@all` last. There are no `@everyone` or `@user` rows. The picker opens at an `@` that isn't glued to a letter, digit or underscore, and the query is the whole run of non-space text after it, so `@å` lists a bot named Ångström. A bot matches when the query starts its handle or any word of its name, both sides NFC-normalised and lowercased and never accent-folded, so `å` finds Ångström and `Å` doesn't find Ada. Rows keep roster order. The textarea carries `aria-activedescendant`, and each option has an id.
- **Keys are one pure table.** `keyAction` maps the key, Shift, "an input method is composing" and "the picker has rows" to `next`, `prev`, `pick`, `close`, `send` or `none`. While composing, every key is `none`, because the key belongs to the input method (WebKitGTK reports some only as `keyCode` 229). With rows, Enter and Tab pick, so Enter with no matching row sends, which keeps what the composer did.
- **The stand-in keeps its own port of Hermes's rule.** `resolveMentions` in `fakeGroups.ts` is written from Hermes's source and must not import `roomMentions.ts`. A test reads the file and fails if it does. A fake that shared the client's reader would make every test of "@cleo reaches only Cleo" pass with any rule at all.
- **Hermes's own code is the oracle for both.** `room-mention-vectors.py` lifts `_MENTION_RE` and `resolve_mentions` out of a Hermes checkout by `ast`, since the package doesn't import without Hermes's dependencies. It runs them over 500 cases, the owner's examples, the four letters at the head and tail of a handle and a seeded random corpus, for both values of `default_all`. It records the commit and a hash of the two nodes' source. The vectors test replays every case against `goesTo` and against the stand-in's `resolveMentions` in both modes, and `--check <hermes-src>` fails when a Hermes build's two nodes hash differently. Bumping Hermes is one command.
- **Seats get their look once.** `seatsShown` joins a seat to its bot's current name, colour, picture and description. `roomMentions.ts` is generic over the seat and never learns about `Bot` or the locale. The words for each note are in `groupRooms.goesTo` in the catalogue (ADR 0100).

## Considered options

- **The stand-in imports the client's reader.** Smallest diff and no drift. Rejected for the reason above, and because it would have left the four-letter gap invisible.
- **Ask Hermes.** A dry-run call per keystroke would be exact. Rejected: `groups.*` has no such method at `f0d94882`, the fix has to work against the Hermes that runs today, and the notes about a trailing mark, a glued `@` and code still need a client-side reader.
- **A route and a separate list of issues.** Rejected: two scans can disagree, and the pane would join them by offset. One `Mention` union carries both.
- **A record of `{seats, everyone, warnings: {severity, message}[]}`.** Rejected: it allows `everyone: true` with seats, an empty list of seats and a severity that contradicts its kind, and it puts English in the domain layer.
- **A hand scanner for code.** Rejected: it would be a second, partly right Markdown reader.
- **Chips above the text, or highlighting inside it.** Rejected by the owner's choice of a line under the message box. The offsets in `Mention` would support highlighting later without a change of type.
- **Folding accents in the picker.** Rejected by the owner: typing `Å` must not find Ada.
- **Ranking a handle or first-word match above a later word's.** Rejected for roster order, which is stable while typing and is the order the bots answer in.
- **Warning only when the text has an `@`.** Rejected: the plain "everyone" outcome is the surprise most worth seeing.

## Consequences

- The vectors can go stale without CI noticing, because CI has no Hermes checkout. `python3 -I scripts/room-mention-vectors.py --check <hermes-src>` against the build a server runs is the catch. The real-Hermes verification (`real-hermes up`) runs it against the source of the Hermes it starts and stops when the vectors no longer describe it.
- The repo holds a Python script and a generated JSON file, and `fast-check` is a dev dependency.
- A name that starts with a non-ASCII letter, such as `@Åda`, isn't captured by Hermes's regex, so the line says nothing about it and the message goes to everyone.
- A seat whose handle isn't a legal Hermes handle (`handle` is the profile name, ADR 0210) can't be mentioned. That was already so, and it isn't fixed here (#61).
- The line reserves one row of height under the message box, and a note adds a row.
- Left out: mentions outside Group rooms (Bot Chat, regular chats, `message_agent`; #58), a preview of the pull-in round, chips, and reporting the long-s quirk to Hermes.
