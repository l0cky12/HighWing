# New bot

Bots mode's New bot, and Settings → Profiles' New profile, open the name dialog (ADR 0231): one name box, Create, Skip and Cancel. A faint line under the box names the id Hermes's own clients will show. Create makes the profile with the profile in use's model (only when that profile has its own), writes the typed name as the bot's name in Bot Mode, and opens the new bot's Bot Chat as a Bot visit, where Bot setup's brief is seeded hidden and a hidden begin turn starts the bot's first reply. Below Hermes 0.23.2, or without Bot Mode, Create makes the bot from the name and model only and sends no brief. Skip has Start blank (the bot, its Bot Chat empty, no brief) and Copy a bot… (Clone profile with the name filled in). Edit bot and Edit profile keep their Persona field and its Write with AI; Edit persona… in a bot's right-click menu opens Edit bot there. Set up again… in that menu asks Keep history or Start fresh, then the bot says how it's set up now and its card shows each change as before → after. The card's Picture row offers one of Highwing's own pictures, named by the bot, over a strip of the whole set, with Upload your own… (ADR 0236). Upload your own… and Edit bot's picture open one picker, **Choose a picture**, with a Pictures tab of Highwing's set and an Upload tab that takes a PNG, JPEG or WebP, then crops it to the circle (ADR 0243).

## Sub-features

- `new-bot-dialog`: the dialog empty, then with a name and the id line, then with Skip's menu open.
- `new-bot-id`: a taken or reserved id gets `-2` in the id line and in the create.
- `new-bot-create`: Create sends one `POST /api/profiles` with the name's id alone (or with the model in use), writes the name in Bot Mode, and opens the Bot Chat with the brief seeded hidden and one hidden begin turn.
- `new-bot-old-hermes`: below 0.23.2 the dialog says why there's no interview, and Create sends no brief.
- `new-bot-blank`: Start blank opens the Bot Chat empty, with no brief.
- `new-bot-copy`: Copy a bot… opens Clone profile with the id filled in.
- `new-bot-picture`: the card's Picture row: the bot's pick ticked with why, the strip with the pick marked and moved by the arrow keys, Upload your own… opening the picker on its Upload tab, and after Set it up the picture in the bot's row, read back by `profiles.get_asset`.
- `new-bot-mcp`: the card's MCP servers: the command shown first, Connect's write-only field, an OAuth server named but not tickable, and after Set it up `reload.mcp` on the Bot Chat, or Reload MCP servers while a reply runs.
- `new-bot-whole-flow`: on a real Hermes, the name dialog, Create, the five questions, the card, Connect, Set it up and the card after, then Set up again with Keep history and with Start fresh, each read back from Hermes.
- `set-up-again`: Keep history keeps the Bot Chat and memory and sends one hidden brief; Start fresh archives the Bot Chat, deletes the counted memory entries and opens a new seeded one.
- `picture-picker`: Edit bot's **Choose a picture…** (or **Change the picture**) opens the **Choose a picture** dialog: a Pictures tab of 12 (`[role=radio]`) and an Upload tab ("Drag, drop, or paste an image", **Browse files**, "PNG, JPEG or WebP"). An image pasted or picked there opens the crop step, "Fit the picture to the circle", with a Zoom range and **Use picture**.
- `edit-persona-rewrite`: Edit bot's Persona, Write with AI, the field holding the rewrite, Undo, and a failed rewrite that leaves the persona as typed.

## How to get to it (user POV)

- The chat list's **Bots** tab → **New bot** (+) above the bots.
- Settings → Profiles → **New profile** shows the same dialog.
- A right-click on a bot's row in the **Bots** tab → **Set up again…**, on a Hermes that runs Bot setup (0.23.2 or later). On the stand-in the menu reads Chat, Settings, Edit persona…, Clone…, Pin, Hide, Delete.
- A right-click on a bot's row in the **Bots** tab → **Settings** opens Edit bot, and → **Edit persona…** opens it with focus in Persona.

## Driving it with wd.mjs

Preconditions: `hv up`, signed in per [sign-in.md](sign-in.md). A stand-in that reports a version older than 0.23.2 takes the no-interview path; the real-Hermes sandbox (`RH_VENV=~/.cache/hermes-v0232/venv real-hermes up`) reports 0.23.2.

- **Open it.** `$S/wd.mjs click '[role=tab][data-mode=bots]'`, `$S/wd.mjs click button "New bot"`, `$S/wd.mjs wait '[role=dialog]' "New bot"`. The name box has focus.
- **Name.** `$S/wd.mjs fill input "Name" -- "Travel Buddy"`, `$S/wd.mjs wait .set-hint "travel-buddy"`.
- **Skip.** `$S/wd.mjs click button "Skip"`, `$S/wd.mjs wait '[role=menu]' "Start blank"`. Escape closes the menu only; a second Escape closes the dialog.
- **Create.** `$S/wd.mjs click button "Create"`, `$S/wd.mjs gone .profile-dialog`. The app is on the new bot's profile with its Bot Chat open. `$S/hv state` shows the create body under `profileCreates`; the real sandbox's stored rows (`GET /api/sessions/<id>/messages`) hold the brief and the begin turn, both `display_kind: hidden`.
- **Start blank.** Open it, name it, **Skip** → **Start blank**: the Bot Chat opens empty and no `prompt.submit` is sent.
- **Copy a bot.** Open it, name it, **Skip** → **Copy a bot…**: Clone profile opens with the id in "New profile's name".
- **MCP servers on the card.** Once the bot's card names an MCP server (`mcp: [{"catalog": …}]` or a `copy` with `mcp`), its row is under `'.msg.returned.bot-setup[data-card] [aria-label="MCP servers"]'`. `$S/wd.mjs click button "Connect"`, then type into the `input[type=password]` under the row and `$S/wd.mjs click '.bot-setup-connect button' "Connect"`: nothing reaches Hermes until **Set it up**, and Connect opened again shows an empty field. After Set it up, `$S/hv state` (or the real sandbox's request log) shows the add or install with the typed value, then one `reload.mcp {session_id, confirm: true}` before the hidden ready turn. With a reply running in any chat the row waits with **Reload MCP servers** instead. The real proof that the bot reaches the server is the "MCP copy" test in `src/hermes/botSetupSpikes.live.test.ts`, which calls its tool from the Bot Chat.
- **The whole flow on a real Hermes.** Run the sandbox with the `mcp` SDK on its path (copy it in as the comment at the top of `src/hermes/botSetupSpikes.live.test.ts` says): `RH_VENV=~/.cache/hermes-v0232/venv RH_PYTHONPATH=<mcp sdk dir> $S/real-hermes up "$HOME/.cache/hermes-verify/rh-new-bot"`. Run the `export RH_DIR=…` it prints, then `$S/hv up --dashboard "$(cat "$RH_DIR/url")"`, `$S/wd.mjs open`, and sign in per [sign-in.md](sign-in.md) with that URL, user `verify` and password `verify-pass`: it says "Reached Hermes 0.23.2"; Skip Model providers. Its model stub runs the interview: it asks the five questions, then writes the block from the answers, using only names its INVENTORY lists. Each theme is its own pass, from `real-hermes up` through *Cleanup*. After signing in, `$S/wd.mjs click button Settings`, `$S/wd.mjs click '[role=tab]' Appearance`, `$S/wd.mjs click '[role=radio]' Light` (or `Dark`), `$S/wd.mjs click button "Back to chat"`. Each `shot` below takes the theme as a prefix, such as `$S/wd.mjs shot light-01-name-dialog`.
  - *A bot to copy from.* Add `brave-search` to `ada` per [mcp-servers.md](mcp-servers.md) **Add**, after `$S/wd.mjs select select "Profile whose MCP servers are shown" -- ada`: command `npx`, arguments `-y` and `@brave/brave-search-mcp-server`, variable `BRAVE_API_KEY` with any value.
  - *Name and Create.* **Open it**, **Name** ("Travel Buddy"), `$S/wd.mjs shot <theme>-01-name-dialog`, `$S/wd.mjs click button Create`, `$S/wd.mjs wait '.msg.assistant' "What should I call you?" 120000`, `$S/wd.mjs wait .transcript "Setup started"`, `$S/wd.mjs shot <theme>-02-setup-started`. `$S/wd.mjs count '.transcript .msg.user'` prints 0: the brief and the begin turn are hidden.
  - *The interview.* For each answer, `$S/wd.mjs fill 'textarea[data-composer]' -- "<answer>"`, `$S/wd.mjs press Enter`, then wait for the next question: "Liam" → "What do you want me to help with?"; "Planning weekend trips with maps and web search" → "never do, or always check with you first?"; "Never book or pay for anything, and check with me before emailing anyone" → "Which apps or services should I work with?"; "Kiwi for flights, and Linear for my to-do list" → "copy anything from one of your other bots"; "Yes, copy brave-search from Ada" → "Here's how I'd set myself up.". `$S/wd.mjs shot <theme>-03-question-5` before the last answer.
  - *The card.* `$S/wd.mjs wait '.msg.returned.bot-setup[data-card]' "Set it up"`. It shows Picture · Plane, ticked, with "For travel and trips." over the strip of 12 pictures, Remember: call you Liam, `maps` and `web` as already set, `kiwi` from the catalog, `linear` with "It signs in with OAuth, so the card can't add it.", and `brave-search` "From Ada" with "Needs BRAVE_API_KEY". The bot's row, `.sb-bots .bots-row[data-profile=travel-buddy] .bots-preview`, previews "Thanks, Liam. Here's how I'd set myself up.", never the block. Turn the wheel over the transcript to shoot it: `$S/wd.mjs wheel .transcript -- -400` toward the card's top and `$S/wd.mjs shot <theme>-04-card-before-top`, then `-- 2000` to the foot and `$S/wd.mjs shot <theme>-05-card-before-bottom`.
  - *Connect.* `$S/wd.mjs click '.msg.returned.bot-setup [aria-label="MCP servers"] button' Connect`, `$S/wd.mjs fill 'input[type=password]' BRAVE_API_KEY -- <key>`, `$S/wd.mjs click '.bot-setup-connect button' Connect`, `$S/wd.mjs wait '.msg.returned.bot-setup' "Ready. Highwing sends it to Hermes when you press Set it up."`. `$S/wd.mjs shot <theme>-06-connect-ready`. `grep -rlI --exclude=cookies.txt <key> "$RH_DIR"` prints nothing yet.
  - *Set it up.* `$S/wd.mjs click '.msg.returned.bot-setup button' "Set it up"`, `$S/wd.mjs wait '.msg.assistant' "I'm set up." 240000`. The card says "6 of 6 applied and read back.", the bot's row in Bots mode shows the plane, both MCP rows "Added, and Hermes reloaded it.", Restart "Hermes restarted Travel Buddy with it." and "Nothing to change.". `$S/wd.mjs shot <theme>-07-card-after` (wheel to the top and foot as before, if it needs two). Now `grep -rlI --exclude=cookies.txt <key> "$RH_DIR"` names `profiles/travel-buddy/config.yaml`; that profile's `profile.yaml`, `SOUL.md` and `memories/` hold the description, the persona and "The owner wants to be called Liam.".
  - *Keep history.* `$S/wd.mjs rightclick '.sb-bots .bots-row[data-profile=travel-buddy] .bots-open'`, `$S/wd.mjs click '[role=menuitem]' "Set up again…"`, `$S/wd.mjs wait '[role=dialog]' "Set up Travel Buddy again?"`. `$S/wd.mjs click '[role=dialog] input[type=radio]' "Start fresh"` shows "Deletes Travel Buddy's 1 memory entry."; `$S/wd.mjs shot <theme>-08-start-fresh-picked`; pick `"Keep history"` again and `$S/wd.mjs click '[role=dialog] button' "Set up again"`. The bot answers "I'm set up as: Planning weekend trips with maps and web search. What would you like to change?" under the earlier history. Answer "Plans weekend trips by train. Work without the terminal, and no humanizer skill.": the card "Set up Travel Buddy again" shows the description as before → after, `humanizer` and `terminal` On → Off, and "3 changes. Nothing changes until you press Set it up."; it must show no "applied and read back" yet, and the row previews "Here's the change. Everything else stays as it is.". `$S/wd.mjs shot <theme>-09-again-card`. Set it up writes the description, `humanizer` under `skills.disabled` and `terminal` out of `platform_toolsets.cli`.
  - *Start fresh.* The same menu, `"Start fresh"`, then `$S/wd.mjs click '[role=dialog] button' "Start fresh"` and `$S/wd.mjs wait '.msg.assistant' "I'm set up as: Plans weekend trips by train. What would you like to change?" 120000`. `$S/wd.mjs count '.transcript .msg'` prints 1, and `$S/wd.mjs shot <theme>-10-fresh-started`. Sign in to the dashboard's API once with `curl -fsS -c "$RH_DIR/cookies.txt" -H 'content-type: application/json' -d '{"provider":"basic","username":"verify","password":"verify-pass"}' "$(cat "$RH_DIR/url")/auth/password-login"`. Then `curl -fsS -b "$RH_DIR/cookies.txt" "$(cat "$RH_DIR/url")/api/sessions?profile=travel-buddy&archived=only"` lists "Earlier Bot Chat with Travel Buddy, <date>", and the profile's `memories/` holds nothing.
  - *Cleanup.* `curl -fsS -b "$RH_DIR/cookies.txt" -X DELETE "$(cat "$RH_DIR/url")/api/profiles/travel-buddy"`, then `$S/hv down` and `$S/real-hermes down`.
- **Picture picker.** In Edit bot, `$S/wd.mjs click button "Choose a picture…"`, `$S/wd.mjs wait '[role=dialog][aria-label="Choose a picture"]'`; `$S/wd.mjs count '[role=radio]'` prints 12. `$S/wd.mjs click '[role=tab]' Upload`, `$S/wd.mjs wait button "Browse files"`. Put a PNG on the run's clipboard as [mark-up.md](mark-up.md) does, then `$S/wd.mjs press Control+v` and `$S/wd.mjs wait '[role=dialog][aria-label="Fit the picture to the circle"]' "" 10000`: it has `input[type=range]` "Zoom", **Cancel** and **Use picture**. **Use picture** puts it in Edit bot, which then also offers **Remove picture**. Closing Edit bot with an edit asks "The changes you made here aren't saved." with **Keep editing** and **Close without saving**.
- **Edit persona.** `$S/wd.mjs rightclick '.sb-bots .bots-row[data-profile=<name>] .bots-open'`, `$S/wd.mjs click '[role=menuitem]' "Edit persona…"`: Edit bot opens with the SOUL.md in `textarea "Persona"` (named by its `<label>`, so `textarea[aria-label=Persona]` matches nothing), focused. Type a rough persona, `$S/wd.mjs wait .set-hint "writes"`, `$S/wd.mjs click button "Write with AI"`, `$S/wd.mjs wait button "Undo"`. With an empty `HV_PERSONA_REPLY` file, Write with AI shows `[role=alert]` "couldn't rewrite" and keeps the text.

## Gotchas

- Throwaway bots made on a real Hermes are deleted through `DELETE /api/profiles/<id>` after the run.
- On the sandbox, Create's toast says "Hermes didn't set the model in use: Unknown provider 'custom'": the stub is wired as a `custom` provider, which Hermes's profile create turns down. The bot still runs on the default model. The toast covers the composer for a few seconds.
- After Start fresh, wait for the bot's new line. The old Bot Chat stays on screen until the new one opens, and its text matches the same waits.
- `wheel` over the card itself can miss: its middle may sit outside the transcript. Turn it over `.transcript`.
- The app reads Hermes's version a few seconds after connecting. A Create before then is treated as a Hermes that runs Bot setup.
- Edit's rewrite runs on the model that writes for the edited bot (ADR 0209): its Text generation model when pinned on the server, else the Writing model from Settings → Model, else its own main model.
- A deterministic stand-in answer proves the app's path, not a provider's rewrite.
