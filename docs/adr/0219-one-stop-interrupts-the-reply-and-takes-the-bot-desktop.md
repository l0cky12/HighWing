# One Stop interrupts the reply and takes the Bot Desktop

> **Accepted.** Phase 4 of computer use (issue #43). Amends [ADR 0147](0147-shortcuts-are-a-command-table-each-handler-asks-and-the-owners-changes-are-a-diff-in-the-display-preferences.md): its command table gains `stopScreen`. Builds on [ADR 0217](0217-one-screencontrol-per-connection-owns-the-viewer-id-and-the-lease.md).

When Hermes drives its Bot Desktop, the owner needs one control that ends what it is doing on the screen. Stopping the reply alone isn't enough. `session.interrupt` ends the turn between two steps (`14-turn-interrupt.jsonl`), but the next turn, or a wake turn, can drive the screen again at once. Hermes's own answer is the lease: while a person holds the screen, every `computer_use` call is refused with `human_has_control` before any Approval (`13-turn-takeover.jsonl`). Until now only the Screen tab's Take over took the lease, and only on a live stream.

## Decisions

- **A reply's Stop takes the screen when the turn used it.** `Hermes.stop(chatId)` keeps its contract and, when the chat's current turn has made a `computer_use` call (`screenUse(chat)?.running`), calls `ScreenControl.hold("Stopped from Highwing")` alongside `session.interrupt`. The composer's Stop and the Stop on a live run's card both call it. A reply that made no `computer_use` call is stopped as before, and no lease is asked for.
- **The interrupt never waits for the screen.** Both go out together once Hermes has accepted the message. A hold that fails, or finds no screen, adds an error line to the chat with Hermes's reason: "Stopped the reply, but couldn't take the Bot Desktop: …".
- **The panic Stop takes the screen regardless.** `Hermes.stopScreen()` stops every reply in the shown profile whose turn is using the Bot Desktop and holds the screen even when none is. It answers `StopScreen = { stopped: string[]; hold: HoldOutcome }`, and App shows that as a notice. It is idempotent: a reply already stopping is left alone, and a screen this connection already holds answers `already` with no request. It acts on the composer target's connection only (ADR 0125), not on background ones.
- **`stopScreen` is a command in the table, `Ctrl+.` by default.** It is app-wide and rebindable, and it fires from inside the composer too, since it has Ctrl. `checkChord` accepts it and `conflicts` finds no clash with the defaults. ADR 0147's rule still holds: no bare key stops a reply outside a text field.
- **`hermes-chat --stop` asks the running app for the panic Stop.** It reaches the running app as a chat link does ([ADR 0037](0037-chat-links-name-ids-only-and-open-after-checks.md)): `Request::Stop` over the session bus (method `Stop`) or the Windows pipe, then an event to the window, `stop-requested`. A link is taken once, by an inbox that outlives the sign-in screen. A Stop needs a window connected to Hermes, so Rust keeps it (`stop.rs`) until a window peeks and acknowledges it (`stop_pending_request`, `stop_ack_request`). The window listens only while its composer target is connected: one shown from cached chats while it still connects, or while it reconnects, leaves the request in Rust and takes it once connected. Run with no Highwing running, it starts the app, and the request waits up to two minutes for a connected window. That wait was first built for `--screenshot`, which is gone with screenshot capture ([ADR 0212](0212-screenshot-capture-is-removed-and-its-staging-folder-stays-for-pasted-files-and-annotations.md)), so `--stop` is now the only request that waits for one. This is the desktop's key for a panic Stop from any app, as `--toggle` is for showing the window, since a global shortcut is the desktop's job ([ADR 0107](0107-the-global-shortcut-is-registered-by-the-desktop-it-runs-on.md) is superseded).
- **A lease taken by Stop is held with no stream.** `hold()` mints a viewer with `display.observe` and acquires the lease without opening the Screen's stream. The recording `16-hold-no-stream.jsonl` shows Hermes keeps such a hold: it stayed `human` for 105 seconds, across seven status reads, until it was released.
- **Opening and closing the Screen tab still hands back.** The Screen tab's rule is unchanged: a stream it opened and then closes gives the screen back to Hermes. So opening the Screen to look after a Stop, then closing it, returns control to the agent. Hand back on the card, on the note above the composer, or in the Screen does the same on purpose.
- **The card counts.** A live run's head reads `step N · m:ss`, ticking once a second only while the run is live, and `N steps · m:ss` after. The time runs from the first step's start to the last step's end. A run read from history, whose steps have no times, shows only its count.
- **After a Stop, the run says who holds the screen.** The stopped run's card shows "You hold the screen" with Hand back. The next `computer_use` call is refused `human_has_control`, and the note above the composer offers Hand back too.

## Considered options

- **Stop only the reply, and leave taking the screen to the Screen tab.** Rejected: the owner would need two actions, and the next turn could act on the screen in between.
- **Take the screen on every Stop.** Rejected: a plain chat's Stop would take a Bot Desktop it never touched and refuse the next computer-use turn for no reason.
- **Keep a Stop-taken hold when the Screen tab closes.** Rejected for now: the Screen tab would need to know why the screen was taken, and Hand back is one press away wherever the hold is shown.
- **A global shortcut for the panic Stop.** Rejected for the reasons in ADR 0107. `hermes-chat --stop` bound to a desktop key covers it.
- **Stop background connections too.** Rejected: a background connection changes nothing on its server (ADR 0125), and its screen may not be the one the owner is looking at.

## Consequences

- One press stops the agent on the screen, and the screen stays the owner's until they hand it back.
- A Stop during a computer-use turn sends `display.observe` and `display.lease.acquire` beside `session.interrupt`. FakeHermes's `computerUseTurn` ends between calls on the interrupt and answers the next call `human_has_control` while the lease is the owner's, as Hermes does.
- A new desktop request is a `Request` variant in `remote.rs`, with a bus method and a pipe case. One that needs a signed-in window also waits in Rust, as `stop.rs` does, with a listener in the webview like `tauriStop.ts`.
- An update's restart drops `--stop` from its arguments, as it drops `--show`, `--toggle` and a chat link, so the new app doesn't take the screen again.
